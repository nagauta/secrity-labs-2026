# secrity-labs-2026 — セキュリティ学習ラボ

IPA「[安全なウェブサイトの作り方](https://www.ipa.go.jp/security/vuln/websecurity/about.html)」で
解説される主要な脆弱性を、**インターネットから隔離された Docker 環境**で再現する教材です。
攻撃の仕組みを手を動かして理解し、同時に「どう直すか」も学びます。

実装言語は **TypeScript**（target は Hono、attacker は Node 標準モジュール、どちらも `tsx` で実行）。

## ⚠️ 安全のための大前提

- **ローカル隔離**: 公開ポートは `127.0.0.1` のみにバインド。外部ネットワークへは出しません。
- **教育目的のみ**: 意図的に脆弱なアプリです。本番・公開サーバには絶対に置かないこと。
- **自分の環境だけが対象**: ラボ内の自分のコンテナ以外を攻撃する用途には使いません。
- DVWA / OWASP WebGoat / Juice Shop と同じカテゴリの、定番の学習用やられアプリです。

## 構成

| コンテナ | 役割 | 公開先 |
|----------|------|--------|
| `target`   | Hono 製のやられ役SNS「つなぐ」（`/sns/widget` に埋め込み「いいね」ボタン） | `127.0.0.1:8080` |
| `attacker` | おとりページ `evil-sns.html` を配信する静的サーバ | `127.0.0.1:9090` |

両コンテナは Docker ネットワーク `labnet` に属します。

## モジュール1: クリックジャッキング（ライクジャッキング）

2010年に Facebook で流行した「いいね！」ボタン乗っ取り（ライクジャッキング）の
再現です。標的の「いいね」ボタンを透明で重ね、別の操作を押させることで、
ログイン中の本人として勝手に「いいね」させ、拡散投稿を本人のタイムラインに流します。

### 起動

```bash
docker compose up --build
```

### 攻撃を体験する

1. ブラウザで `http://localhost:9090/` を開く → 「衝撃映像」を餌にしたおとりページ。
2. 「▶ 再生する」を押す。
3. 実際には裏に透明で重なった SNS『つなぐ』の「👍 いいね！」が押され、拡散投稿
   （例: `【拡散中】絶対見て！衝撃映像 bit.ly/xxxx`）に本人としていいねしてしまう。
4. いいねを盗んだ直後、攻撃者ページはオーバーレイを外して**本物のネコ動画を再生**する。
   利用者は「普通に再生できた」と思い、乗っ取りに気づかない。
5. `http://localhost:8080/sns` を直接開くと、押した覚えのない投稿が自分のタイムラインに
   いいね済みで並んでいることを確認できる（＝友達のフィードにも流れて拡散する）。

> 💡 右上の学習用コントロールで、仕掛けと対策を観察できます。
> - **「オーバーレイ(いいねボタン)を表示」**: 再生ボタンの上に透明で重ねた
>   「いいね」ボタンと、**攻撃者の狙い（シナリオ解説）**が表示されます。
> - **「🛡 対策を有効化（フレーム化を拒否）」**: 標的が `X-Frame-Options: DENY` を
>   返した状態を再現します。いいねボタンが埋め込めず（「フレーム表示を拒否」の表示）、
>   再生を押しても**いいねは盗まれません**（＝攻撃失敗）。状態バッジが「脆弱／対策済み」で
>   切り替わります。

### なぜ成立するのか（脆弱点）

埋め込み用ウィジェット `/sns/widget` が、フレーム化を禁止するレスポンスヘッダ
（`X-Frame-Options` も `Content-Security-Policy: frame-ancestors`）を
**一切返していない**ため、任意の外部サイトから `<iframe>` で重ねられてしまいます。
該当箇所は `target/server.ts` の `/sns/widget` ハンドラとその上のコメントを参照。

### 対策

`target/server.ts` 冒頭にコメントアウトされている `app.use(...)` を有効化すると、
以下のどちらか（両方でも可）が全レスポンスに付与され、攻撃が成立しなくなります。

- `X-Frame-Options: DENY` — iframe 埋め込みを全面拒否（古くからある専用ヘッダ）
- `Content-Security-Policy: frame-ancestors 'none'` — 祖先フレームを一切許可しない（現代的な方法）

有効化して `docker compose up --build` で再起動し、同じ手順で攻撃が
**失敗する**（iframe がブロックされ、再生ボタンを押しても何も起きない）ことを確認してください。

> 補足: 本物の Facebook は攻撃者サイトと別ドメイン（cross-site）のため、現代ブラウザの
> サードパーティ Cookie ブロックや SameSite Cookie も防御として働きます。本ラボは
> `localhost` 同士（same-site）なので、その影響を受けずに仕組みを観察できるよう、
> セッションではなく単純なサーバ状態で「ログイン中の本人」を再現しています。

### 学習後のリセット

```bash
curl -X POST http://localhost:8080/sns/reset
```
